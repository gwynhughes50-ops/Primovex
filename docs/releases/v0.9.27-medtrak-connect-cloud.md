# v0.9.27 - MedTrak Connect Cloud Foundation

## Summary
Sprint 27 introduces the first backend layer for MedTrak Connect. The frontend no longer needs to be designed around direct vendor access. Provider integrations now have a secure cloud boundary for sync, ingestion, alert creation and future webhooks.

## Added
- `functions/` Firebase Cloud Functions project.
- Callable `connectCloudHealth` endpoint.
- Callable `syncConnectProvider` endpoint.
- Callable `ingestConnectReading` endpoint.
- Scheduled simulator sync every 15 minutes.
- Backend provider factory.
- Simulator backend provider.
- Tuya backend shell with server-side secret boundary.
- Device sync service.
- Connect alert service.
- Connect event bus.
- Frontend `connectCloudClient`.
- Connect Cloud status panel on the Connect page.
- Firestore rules for provider health and Connect events.

## Security
- Tuya Access Secret must never be stored in React or Firestore client-writable documents.
- Vendor credentials belong in Firebase Functions environment variables or Secret Manager.
- Cloud Functions use the Admin SDK for device sync, readings, alerts and event writes.

## Manual steps
1. Replace the Sprint 27 files.
2. Run `npm run build` from the main app.
3. Run `cd functions && npm install` before deploying functions.
4. Deploy functions when ready with `firebase deploy --only functions`.
5. Deploy Firestore rules after reviewing changes.

## Notes
The Tuya provider is intentionally a backend-ready shell in this release. Real Tuya signing/API polling should be added in Sprint 28 once development credentials and test hardware are available.
